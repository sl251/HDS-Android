# 消息诊断怎么看

发出消息后，角色一直没回，先别急着重装。打开“空间 → 消息诊断”，找到刚才那条消息，看看停在哪一步。有模型调用失败时，聊天气泡下方也会出现“该消息模型调用失败 · 原因标签 · 查看诊断”，点“查看诊断”会直接找到那条消息，并展开明细。

## 先看消息卡片

一条消息对应一张卡片。卡片上方是消息前 40 个字和时间，例如“3 分钟前”；超过一天会显示日期。如果消息已经不在当前加载的聊天记录里，会显示消息编号，不会编造正文。预览只从聊天中读取，不写入诊断文件。

每张卡片有六步：**提交 → 处理 → 模型 → 决策 → 语音 → 投递**。窄屏会换行，仍按编号 1 到 6 阅读。

| 步骤 | 它在做什么 |
| --- | --- |
| 1. 提交 | 把你的消息交给故事核心。 |
| 2. 处理 | 整理这一回合；接连发送的几条消息可能一起处理。 |
| 3. 模型 | 请求模型生成内容。模型可能在失败后再次尝试，或使用你设置的备用连接。 |
| 4. 决策 | 角色决定立即回复、稍后回复，或本轮不回复。 |
| 5. 语音 | 本轮需要语音时生成语音；文字回复可以跳过。 |
| 6. 投递 | 把回复送到聊天里。只有实际投递记录能说明这一步的结果。 |

高亮的步骤是当前关注的位置。红色并带有“失败”的步骤出了问题，先读卡片顶部的“怎么办”。“未记录”表示没有足够证据，不能当成已经成功。语音失败后仍可能收到文字，具体看投递记录。

“本轮不回复”是角色的实际决定；“稍后回复”说明还在等待后续投递。这两种情况都不等于连接坏了。若失败后再次尝试成功，卡片会显示“模型重试后已恢复”，旧的失败仍在明细中保留。

顶部的“全部”显示最近的消息，“失败”只显示当前仍有失败的卡片，“最新”显示最近 20 条。列表最多显示 200 条消息；要找更早的消息，可在“查看范围”中选择消息编号。从聊天跳过来时会自动选中对应消息，选“全部记录”即可回到全局。

## 常见原因与自己能做的事

界面中的“模型中心”入口是 **空间 → 模型连接**。超时项位于 **空间 → 高级设置 → 生成与备用切换 → 请求超时（秒）**；检查密钥后可在模型连接页面点“测试当前连接”。修改后如出现“新配置已就绪”，点“立即重启生效”。

| 原因标签（原因码） | 建议先做什么 |
| --- | --- |
| 请求超时（timeout） | 模型没在限定时间内返回。可把超时调大，例如 120 秒，或换更快的模型、连接。超时不能确认远端是否完成或计费，不要连续重复发送。 |
| 网络连接失败（network） | 先检查网络是否正常，稍后看自动重试结果。经常发生时，可在模型中心添加备用连接。 |
| 服务商出错（provider_error） | 稍等片刻，留意自动重试；持续出现可检查服务商状态，或使用备用连接。 |
| 触发限流（rate_limit） | 等 1–2 分钟再发，避免连续点发送；持续出现请检查该连接的额度和请求限制。 |
| 限流或额度不足（throttled_or_quota） | 服务商没有明确区分限流和额度问题。先等 1–2 分钟，仍失败再查看账户额度，不要直接认定余额耗尽。 |
| 密钥无效（authentication） | 到模型中心检查 API Key，保存后点“测试连接”。 |
| 无访问权限（permission） | 检查 Key 是否允许访问选中的模型，改完点“测试连接”。 |
| 连接额度耗尽（provider_quota） | 换有余额的连接，或到服务商处充值。 |
| 消息未接收（not_accepted） | 确认故事已经唤醒、没有暂停，再重试发送。 |
| 后台预算已用完（background_budget） | 等预算恢复，或到“空间 → 高级设置”调整后台预算。直接聊天不占该预算。 |
| 请求参数被拒绝（invalid_request） | 检查模型名称、接口格式与生成设置，再测试连接。 |
| 原因未确认（unknown_error） | 展开明细，保留原因码反馈，不要仅凭这一项判断是网络还是余额问题。 |

遇到表格之外的原因码，页面会提示“查看下方明细，可将原因码复制反馈”。语音等步骤也可能有自己的原因码，请结合出问题的步骤阅读。

自动重试有次数、时间和运行条件限制，不保证最终成功。“测试连接”会实际访问服务商，可能产生 API 用量。

## 再看明细

点“展开明细”，事件按时间从早到晚排列。较多时点“显示更多明细”继续查看。耗时用秒显示，例如“1.3 秒”，短于一秒显示“不足 1 秒”。“第 2 次尝试”说明这不是第一次请求，可能增加 API 用量。

本次核心运行产生的调用会显示连接名称。重启前的旧记录仅保存了当时的连接序号，会显示“连接 #1”等；不能按今天的连接顺序推断它当时是哪一家。连接名称只用于当前查看，不写入脱敏诊断文件。

接连发送的消息可能共享一次模型调用，因此它们各自的卡片会出现相同的处理事件，这不表示重复调用了模型。没有关联编号的事件会单独显示，不会按时间强行归到某条消息。

## 清空、保留与反馈

诊断记录保留 7 天，最多 2000 个事件，同时有 1 MiB 大小限制，旧记录会自动清理。因此更早的聊天可能没有诊断；没有记录不代表那条消息从未出过问题。

“清空本故事记录”只清诊断，不删除聊天。清空后显示“一切正常，暂无诊断记录”，这是空列表提示；读取出错或故事没有唤醒时会另外提示。后来新产生的事件仍会被记录。

需要反馈时，可以使用“导出脱敏记录”，并说明哪个步骤失败、原因码、发生时间与是否重试过。若已选择某条消息，导出也只包含这个范围。诊断不会保存正文、人设、密钥或音频；卡片预览来自聊天，请在分享页面截图前检查个人内容。不要发送自己的 API Key。
