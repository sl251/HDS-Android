## 已实现

### 设置与聊天界面

- 空间首页直接进入模型连接、角色与故事、持续生活、语音与音色、通知、界面个性化；另有表情包、消息诊断、高级设置、备份与维护。
- 后台预算、生成参数、固定/弹性节奏、日程、时间导演、长线叙事等放入高级设置。持续生活页集中总开关、主动联系与情绪设置。
- 角色库保留统一的人设/生活配置导入码入口，避免在新的设置分区重复放同一个流程。
- 保留现有玻璃样式与安全区机制；窄屏设置回落单列，诊断弹窗独立滚动、键盘焦点限制在弹窗内。
- 不再按后续回复时间推断“已读”，只显示“核心已接收”；提交中的状态改为“正在提交消息”。
- 保留 9.3 按消息音频展示历史语音的行为，关闭当前语音开关不会改变历史气泡。成功的语音仍为语音气泡，文字稿按需展开，失败保留原文字回退。

### 消息诊断

- 入口：长按消息、消息旁的诊断按钮、空间首页“消息诊断”。
- `runtime/message-diagnostics.ts` 为共用结构化事件记录器。记录提交、回合开始、模型尝试/失败/成功、明确回复决策、表情选择、语音结果、投递、提交的故事记录编号。
- 多条消息合并时，回合保留各消息 ID。立即回复沿异步上下文关联；延迟文字/语音投递通过对应 scriptEntryId 查回原请求。没有确切关联的后续投递单独记录，不按时间猜测关系。
- `scripts/mobile-diagnostics.mjs` 在构建时注入 service/narrator/turn-engine，由原 `mobile-onebot-voice` 插件组合加载。每个替换点要求精确匹配一次，遇上游变更应失败并人工复核。没有修改 upstream 工作树。
- `diagnostics.messages` / `diagnostics.clear` 已接入 host，并加入 9.3 `HdsRuntime.kt` 现有 RPC 白名单；没有引入旧审计分支的契约生成系统。
- 每个故事 profile 的 `message-diagnostics.json` 最多保留 7 天 / 2000 事件 / 1 MiB，重启可读取；未确认完成的工作显示重启中断。新事件同时进入现有 Android 运行日志，使用 `[HDS_EVENT]` 前缀。
- 仅持久化白名单字段，不保存聊天、人设、模型输入输出、密钥、供应商地址或音频。供应商错误正文只在内存中分类，不写入新诊断。
- 支持清空和 SAF 导出；导出先固定当前故事快照，再打开系统文件选择器。大快照保存在应用缓存文件，避免放入 Activity 状态；成功、取消、写入失败都会清理，异常退出的临时文件次日清理。
- UI 每次展示 100 条，可加载更多；查看诊断时定期刷新，不额外请求模型。

### 额度与语音

- 区分供应商明确余额/配额不足、认证失败、无权限、明确限流、无法区分的 429、本机后台预算、本机语音预算、网络/超时。
- 模型诊断记录调用时的连接序号，避免把自定义连接名称或地址写入报告。
- 主叙事明确遇到额度/认证/权限拒绝时，跳过同一轮对同一连接的剩余尝试；仍遵循已配置的备用连接和上游冷却规则。没有改动后续独立回合的重试调度。
- TTS 的 HTTP 402 明确拒绝不再占用未知计费预留；超时和未知计费仍保守保留。没有清空旧预算记录，也没有自动增加限额。
- 未返回有效 voice.willingness 与“意愿低于阈值”分开显示，避免误称模型主动选了文字。
- 在 9.3 原语音桥接 JSON 中增加可选诊断字段；音频字段不变。本地聊天从实际合成结果写入消息诊断，语音设置显示最近一次结果。本机预算沿用 9.3 的总量统计，不虚构分项用量。

### 表情包池隔离

- 每个包增加 `pool: user | character`；旧包未指定 pool 时归用户池，素材和历史引用均保留。
- 用户抽屉、最近使用仅从用户池读取。原生导出仅允许角色池进入 profile/stickers，模型扫描不能看到用户池。
- 管理页可分别导入、删除、重命名，以及复制整个包到另一池。复制仅共享不可变素材字节，包清单和最近使用记录独立。
- 当前为“用户池 / 所有角色使用的角色池”，未增加每个角色独立的第三层分组。
- 角色池修改在下次核心启动生效，界面明确提示。原生启动的快照替换流程继续保留。
- 升级后机器人不会自动沿用旧共享包；用户可明确将需要的包复制到角色池。没有删除旧包或重置故事数据。

## 交给测试 / 构建模型

先执行完整类型检查、host 构建和相关现有测试，再补针对新行为的用例。不要把旧测试中“旧包直接给机器人用”“按时间推断已读”的断言继续当作规格。

1. **构建连接**：`npm run typecheck`、`npm run build:host`；确认三个 overlay 均加载、契约一致。生成后的 host / 前端 / 原生代码必须一起打包，本轮没有更新 `runtime/generated/host.cjs` 或 APK。版本号和发布动作尚未执行。
2. **本地消息真实链路**：立即回复、none、delayed、两条/多条合并、新消息打断、暂停恢复、首条流式回复、模型中断、后台独立投递；确认 ID 不串到另一角色或 QQ 回合。延迟投递重启后需验证 scriptEvent 与脚本记录关联。
3. **错误与重试**：401/402/403、429 rate_limit、429 insufficient_quota、未知 429、网络断开、超时；有/无备用模型。确认确定拒绝不重复同一轮请求，其他上游策略保持。区分本机后台预算、语音预算和供应商余额。
4. **语音**：生成成功只显示语音气泡；失败回退文字；有效低意愿、缺少/非法意愿、冷却、无 Key、预算不足分别解释；402 释放本次预留，超时不释放未知用量；历史音频在关闭语音后仍可播放。覆盖内置、克隆、描述音色，并回归 QQ 现有语音流程。
5. **表情隔离**：旧清单升级、用户池独占、角色池独占、相同字节分别入两池、复制包后独立编辑/删除、重启导出、角色池清空后旧扫描缓存失效。删除包后历史消息和另一池仍可使用；用户池图片不应进入机器人素材目录或提示词目录。
6. **诊断可靠性/隐私**：真实请求 ID、并发回合、清空与在途工作、磁盘写入失败、超大/损坏文件、7 天与条数/容量轮转、重启；日志及导出检索密钥/正文/音频 fixture，必须不存在。SAF 成功、取消、Activity 重建、打开文件选择器后切角色、写入失败、大于 IPC 推荐大小的报告。
7. **界面与升级**：320/360/390dp、大字体、横屏、键盘、三键/手势导航；设置最后一项可见可点，长按与滚动不冲突，弹窗返回/焦点/滚动正确；原有设置、模型 Key、角色、剧情、记忆及语音历史保留。

可优先查看现有 `tests/host.test.ts`、`tests/preview9.test.ts`、`tests/preview91-m3.test.ts`、`tests/message-contract.test.ts`、`tests/m5.test.ts`、`tests/m5-ui.mjs`、Android 语音/表情相关测试，调整或补充真正验证新行为的用例。

## 验证边界

- 尚无本轮真机或可运行 APK 证据，不能宣称用户的额度故障已经复现或消失。若供应商余额确实耗尽，代码不能补足余额。
- 第一阶段完整诊断范围为本地消息。QQ 保留 9.3 原有发送与回退逻辑，不宣称完成 QQ 全链路消息关联。
- 旧消息无法补录；超出保留窗口的关联、缺失 scriptEvent 的后续投递明确保持未知/独立。诊断读取和清空目前需要当前故事核心在线，停止时的 UI 给出唤醒提示。
- 保留原付费功能开关、预算默认值与老用户配置。没有改写模型决策，没有为补充原因增加模型调用。
