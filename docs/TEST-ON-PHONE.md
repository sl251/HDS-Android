# HDS Android 0.1.0-preview.5 真机测试

这是 QQ 本地接入与信箱界面候选包，不是已通过全部验收的完整移植版。真机运行由你验证；本次自动化测试使用固定模型响应，不冒充真实 API 或 Android 结果。

## 安装与首次使用

1. 下载 `HDS-Android-0.1.0-preview.5-arm64.apk`，在 ARM64、Android 8 或以上手机安装。安装包使用本项目自己的固定预览签名，不需要电脑或 Termux。
2. 打开“角色”，导入提供的合成 JSON 样例或自己的 Tavern JSON/标准 tEXt PNG 卡、typ0 下载的 koishi.yml；检查预览再保存。也可手动创建。
3. 打开“设置”，点击“准备本机环境”，等待 APK 内置 Ubuntu/Node/HDS 校验和解包。确保可用空间满足应用显示的实际需求。
4. 在模型中心选择预设或填写自定义 Base URL、API Key，获取模型列表或手动填模型名。分配主叙事、记忆压缩、Alter，再填写你的故事称呼/人设。按“测试当前连接”验证后保存全部设置；这一步真的调用 API，可能有少量费用。
5. 点击“启动 HDS”。状态只有在手机里的 Node/Koishi/HDS/SQLite 认证健康接口实际响应后才显示“运行中”。失败时展开日志，不会用假回复替代。
6. 在“对话”发送一句话，等待 HDS 生成。打开“剧情与记忆”刷新真实剧情与长期事实。角色卡开场白会在本地展示、入账，不会向 QQ 发送。
7. 切换另一个角色会先停止旧运行档案。重新启动后生成独立故事；切回时旧数据库保留。不要通过卸载应用来重装环境，卸载会删除本机故事。

## 已知边界

- 只包含 ARM64 运行器；4 KB/16 KB 页、iQOO/OriginOS 和后台策略均未实测。无法启动请反馈 ABI、页大小、Android/API 与日志。
- QQ 扫码、快捷登录、文本私聊与 @ 群聊为实验接入；真实手机登录与投递尚待验证。空间、媒体和多账号同时在线未实现，不能用“QQ 已连接”代替这些能力已通过。
- 角色卡 V1/V2/V3 JSON 与标准 tEXt PNG；原始字节和未知字段保存。CHARX、iTXt/zTXt、V3 外链资源、扩展脚本、正则与递归世界书执行未完成。
- 世界书支持关键词、secondary/selective、常驻、禁用、大小写、顺序/优先级、前后位置和保守预算。暂不等同 SillyTavern 完整提示编排。
- 备份/恢复、电脑迁移、升级回滚、媒体、浏览器、完整高级设置与费用预算仍待实现。本版不要用于唯一副本的重要长期故事。
- 正常停止会请求核心退出；超时后只结束本应用创建的 PRoot 进程。停止/进程回收边界和未知投递恢复仍需要真机故障测试。

## QQ 首次手机测试

1. 覆盖升级后更新环境，启动 HDS，打开信箱下载组件。取消一次再重新下载，检查错误和进度。
2. 启动 QQ，记录二维码是否出现、耗时与 QQ 日志。用官方 QQ 扫码确认，等消息通道在线；不要分享二维码或登录文件。
3. 自动回复保持关闭，用另一个账号发文字：信箱应收到消息，模型不应调用。
4. 加入测试账号白名单并启用自动回复，再发文字，应获当前角色回复。未授权账号不应触发模型。
5. 手动发送文字，断网再重试，核对结果不明的消息不会静默重发。检查未读与会话。
6. 测试群加入白名单：普通消息不应触发模型，@ 机器人账号才触发。
7. 停止全部、重启 QQ，尝试快捷登录；角色切换后登录记录保留，新角色白名单独立。
8. 断网恢复、锁屏 10 分钟、系统强停分别记录。停止后不应继续自动回复。
