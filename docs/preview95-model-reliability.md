# Preview 9.5：模型调用稳定性与消息诊断重做

本预览围绕一个主题：**模型调用不再莫名失败，失败了也能一眼看懂**。

## 为什么要做

Preview 9.4.1 及之前，用户反馈的模型调用失败大多不是模型真不可用，而是移动端把上游的多层重试简化成了"单次请求、单连接、一刀切 60 秒超时"。一次网络抖动或慢模型就会触发 5 分钟连接冷却，叠加 Android 虚拟机 DNS 不刷新问题，表现为"时好时坏、过一阵又好了"。

三模型独立评审（Gemini 4 Argon / Claude Sonnet 5.5 / GPT-Astra）交叉确认了根因链，本预览按评审结论逐项修复。

## 模型调用修复

- **选择性重试**：超时、网络错误、限流（429，读 Retry-After）、服务商 5xx 自动重试；密钥错误、配额耗尽、权限不足、入参错误直接换下一个连接，不浪费时间也不进冷却。
- **超时分档**：主叙事默认 60→90 秒；新增单轮 240 秒总时限，防止重试叠加成十几分钟的挂死。
- **冷却修正**：只有真正服务商故障才记冷却；认证/配额错误不再把连接打入冷宫。
- **早发回复保护**：流式早发回复已投递给用户后，后续失败不再继续重试生成。
- **网络层加固**：PRoot resolv.conf 追加公共 DNS 兜底，启动与每分钟健康检查时刷新，修复 Wi-Fi/蜂窝切换后 DNS 固化。
- **设置全链路**：重试次数、冷却时长、轮次时限可在模型中心（高级）调整；存档 schema 2→3 原子迁移，只升级恰好等于旧默认值的超时，不动自定义值。

## 消息诊断重做

- 诊断页改为按消息聚合的卡片，一条消息一行：提交 → 处理 → 模型 → 决策 → 语音 → 投递六步管道，走到哪步、哪步红了一目了然。
- 12 类失败原因都配了下一步建议，例如"请求超时——可把模型中心超时调大，或换更快的模型"。
- 聊天页失败消息下方有提示条，点击直接定位到那条消息的诊断卡片。
- 时间显示改秒制与相对时间，连接显示名称，重试次数有角标。
- 详细说明：docs/diagnostics-guide.md。

## 其他改进

- 底部导航支持左右滑动切换（60px 阈值、横向优先判定），带滑动指示条与页面过渡动效，尊重系统"减弱动态效果"。
- 音色工作台弹窗内边距与排版修复，长文案不再紧贴边框。
- 新增七步新手引导（首次打开触发，可跳过、可重看），覆盖聊天、角色、模型连接、故事/收件箱与诊断入口。

## 验证边界

- 模拟器与浏览器端：npm test 165 项、UI 六脚本、Kotlin 单测 14 项全部通过；补丁重放与幂等检查通过。
- 未覆盖：真机换网（Wi-Fi↔蜂窝）、真实付费模型、真机 TTS。请按 docs/TEST-ON-PHONE.md 清单验收，模型调用类问题请附带诊断卡片截图。
