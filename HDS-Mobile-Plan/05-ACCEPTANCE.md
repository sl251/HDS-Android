# 验收、测试与支持范围

本表是待执行测试计划，所有用例初始状态为 NOT RUN。本文不包含实际 APK 测试结果。

## 1. 验证层级

1. 纯模块：卡解析、映射、世界书、协议校验、时间与配额策略。
2. 宿主集成：真实 Koishi/SQLite/HDS，模型与 QQ 用固定响应替身；比较原版与移动宿主的请求和数据库副作用。
3. Android 集成：真实 APK、PRoot、文件选择器、进程监管、Keystore、WebView 与网络。
4. 真实渠道：用户授权的账号/测试群/测试空间与真实模型；结果与 mock 分开。
5. 长时与恢复：强退、系统回收、重启、断网、低存储、升级失败。使用专门测试档案，先备份。

涉及公开发送的用例预先固定账号、对象、内容、可见性和清理步骤，由用户授权或亲自触发；不要向真实好友批量发测试消息。自动 CI 不持有生产 QQ 登录态。

## 3. 性能目标与测法

下面是初始优化目标，未实测。T02 给基线，T16 给达标/未达标及原因。不能靠删除首版功能达标。

| 指标 | 初始目标 | 条件/记录 |
|---|---|---|
| UI 可交互 | iQOO 15 常规冷启动 3 秒内 | 不含首次解包/QQ 登录 |
| 已安装运行时启动 | 30 秒内健康或给具体失败原因 | QQ/HDS 分别计时，不混入扫码等待 |
| 普通导卡 | 5MiB 内 JSON/典型 PNG 2 秒内预览 | 不阻塞主线程，大资源显示进度 |
| 历史列表 | 万条数据分页，首屏本地查询 500ms 目标 | 不一次加载全量剧情/图片 |
| 主界面交互 | 无持续卡顿 | 真机 frame/ANR 与 WebView 版本 |
| 重复动作 | 0 个可确认的重复可见动作 | 故障注入；不宣称网络 exactly-once |
| 稳定性 | 2 小时功能连续测试 + 至少 24 小时观察 | 无内存持续爬升/启动风暴，记录回收 |
| 内存/存储/电量 | 测后制定上线预算 | 所有子进程 PSS、安装峰值、闲置/活跃耗电 |

真实 API 延迟与模型质量不设假定阈值；记录服务商、模型、参数、网络、token 用量。两宿主使用固定输入比较确定性结果，模型随机输出用人工观察补充。

最低计划：iQOO 15；旧 ARM64 手机；其他厂商手机；4KB 与16KB 环境。无法取得额外真机则标未测并收窄支持声明，不用静态检查填满矩阵。

## 5. 自动化检查入口

HDS 上游已有 npm run typecheck 与 npm test，以 T01 固定环境执行。建议新工作区提供以下入口（目前不存在，T04 建立）：

```text
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:contracts
pnpm test:hds-parity
pnpm build
pnpm android:sync
android/gradlew.bat lint testDebugUnitTest assembleDebug
```

运行时 ARM64 构建通常需要 Linux CI 或 ARM64 构建环境，Windows UI 构建成功不代表 guest 原生模块可用。CI 包含 bundle 新鲜度、锁版本、许可证清单和哈希检查。

## 6. 发布门槛

所有强制用例执行通过，尤其 S01—S07、H02—H03、R01—R09 与 iQOO 全链路。设备或授权缺失导致 NOT RUN 不能视为通过；公开发布还须完成依赖分发核查。

允许标明缺项的开发预览，不得标为“完整移植完成”。最终报告需明确设备、未测范围、源码/包校验和及恢复步骤。
