# 给实施模型的提示词

把整个计划文件夹交给模型，不要只给本文件；若能访问当前工作区，直接指定目录。以下已包含用户确认的决定，不必从头询问平台和范围。

## 1. 总提示词（首次实施时复制）

```text
请实际实施 HDS Android 移植项目。

先阅读工作区 HDS-Mobile-Plan/ 中的 00—06 文档、TASK-BOARD.csv 和 sources.lock.json，并遵守工作区适用的仓库指令。这是规划产物，新接口和脚本尚不存在；不要误报为已经实现。

用户已确认：
1. 移植 ISEKAI-MomoiCore/HDS-Interlude Koishi 插件，不是另一个 typ-0 桌面应用。
2. 首版 Android APK，手机独立运行，直接连接模型 API，不依赖电脑/服务器。
3. 尽量还原原版 HDS，角色卡导入必须可用，界面极简。
4. QQ 私聊、群聊、QQ 空间动态全部首版必做，不能擅自推迟空间。
5. 主验收设备 iQOO 15，尽量扩大安卓适配；实际系统版本、内存和页大小应采集。

优先路线是 Kotlin/Capacitor/React + PRoot Ubuntu ARM64 + Node/Koishi/HDS 原核心。参考 deepseek-harness-android 的运行管理和 AstrBot Bubble 的 Linux QQ 安装/账号流程，不移植无关 dsh/AstrBot 业务。HDS 空间依赖 SnowLuma 扩展；安卓注入和分发授权是前期验证点。

本轮先完成 T01—T03。先固定源码、工具链和依赖来源，再做真实 APK 环境的本地 HDS/QQ/空间验证。HDS 原有测试失败、设备缺失、账号操作未授权分别记录。不要先花大量时间做 UI，也不要只给我另一份泛泛计划。

无需重复询问已确认事项。能独立完成的代码、构建、测试和诊断请持续推进；缺设备/账号/授权时，先做好最小复现、可运行探针、测试步骤及所有无依赖工作，再说明具体需要什么。真实 QQ 消息/空间写操作需要具体测试授权，不在普通好友/群里擅自测试。

不得偷偷改成远程客户端、强制 Root、用普通聊天 API 仿冒 HDS、重写全部 HDS、将 mock 当成功，或复制受限代码后当自由分发依赖。不能只做上传按钮就说角色卡已支持，不能因 NapCat 能聊天就说空间可用。

每项提供修改文件、实际命令、设备/版本、PASS/FAIL/NOT RUN 用例和证据路径，同步更新任务表。完成 G0 后说明采用后端、实际边界、未决事项及下一批任务。架构变更先形成有证据的 ADR，并保持用户需求不变。
```
