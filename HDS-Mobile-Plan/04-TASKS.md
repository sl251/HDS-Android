## T01 — 固定基线、构建工具链与依赖边界

- 输入：01-RESEARCH、sources.lock.json、用户要求。
- 工作：检出固定 HDS 与参考源码；检查仓库指令；生成 feature-parity.csv，覆盖全部 HDS 配置分区和命令。确定 SDK/NDK/JDK/AGP/Gradle/Node/pnpm 的实际可构建组合，运行 HDS 原始类型检查与测试，记录已有失败。
- 核心细节：建立 HDS 真正 bundle 构建方式；锁定 Koishi/http/sqlite/OneBot；记录 SQLite 原生依赖的 ARM64 构建方式。调查 SnowLuma、Linux QQ、runner 的使用/分发条件，不要求用户提供参考项目团队签名。
- 交付：baseline.md、toolchain.lock、license-inventory.csv、feature-parity.csv、可复现 HDS 构建命令。
- 完成门槛：能解释每个必需二进制从哪里来、如何复现/校验；现有失败与本项目失败可区分；受限组件不得未经核清进入发布构建。

## T02 — iQOO 15 本地运行技术验证

- 依赖：T01。
- 工作：采集 iQOO 的真实系统/ABI/页大小；制作最小 probe APK，在应用私有目录运行 PRoot、Node、Koishi、SQLite 和 HDS；验证启动、写入、重启读取。随后验证 Linux QQ 和未修改的候选 SnowLuma ARM64 包；记录注入前后状态、日志与退出码。
- 要求：Termux 探针只能作诊断辅助，不能代替最终 app UID/SELinux/目录权限下验证；不靠 Root/Shizuku 才成功后声称免 Root。
- 交付：probe APK、复现脚本、脱敏设备报告、内存/存储/冷启动初测。
- 完成门槛：真实 Android 环境通过 Node/SQLite/HDS；QQ 注入是否成立有证据。失败时明确是 ABI、页大小、ptrace、执行权限、依赖还是登录问题。

## T03 — QQ 私聊/群聊/空间与后端选型验证

- 依赖：T02；涉及真实写操作时需测试账号与动作授权。
- 工作：使用 Koishi OneBot adapter 连接候选后端；验证私聊、群聊、图片、引用。逐项验证空间读列表、好友动态、发帖、评论、点赞以及回执字段；验证重连、过期登录和一次未知结果。
- 后端决策：优先采用无需修改的 SnowLuma 全功能路径；验证 NapCat 可达范围。若全功能失败，调查本地等价方案并列证据，不能自动改远程或砍空间。禁止为绕过发布限制直接复制受限代码。
- 交付：qq-capability-matrix.json、qzone-contract-fixtures、ADR-qq-backend.md、G0-report.md。
- G0 门槛：iQOO 本地全功能有可复现结果；缺少某项时标 pending/failed，并保留发布阻断。采用后端、版本、QQ 版本及适配补丁唯一确定。

## T04 — 工程骨架与协议

- 依赖：T01。
- 工作：建立 02 中的工作区布局、Capacitor/Kotlin、contracts、测试/构建脚本；新包名和自有签名策略。创建 typed 原生桥、schema 校验及显式 browser mock。
- 交付：可安装空壳 APK、contracts 文档、CI、开发启动说明。
- 完成门槛：全新机器按说明可 build；UI 显示 mock 时有标识；不存在 DSH 的账号/签名/自动化权限残留。

## T05 — 安装器与进程监管

- 依赖：T04；运行参数采用 T02 结果。
- 工作：清单、哈希、分步安装、失败重试、空间检查、staging 原子切换；实现 RuntimeSupervisor 和独立进程状态。QQ 依赖作为独立可恢复阶段，数据目录与环境隔离。
- 交付：安装/启动原型与失败注入报告。
- 完成门槛：下载中断、解包中断、磁盘不足、端口占用都可恢复；重复启动不产生双实例；关闭 Activity 不误杀托管任务；只结束自己创建的进程。

## T06 — HDS 宿主、Mobile API 与本地聊天

- 依赖：T05、T04。
- 工作：真正加载 HDS rc51；通过服务层暴露设置、快照、消息与记忆；local adapter 实现本地身份、投递回执和端点状态；HDS 缺少 local 类型时做最小补丁；普通 QQ 模式保持桌面 IPC bridge 关闭。
- 交付：可本地聊天 APK、API 契约测试、upstream-patches.md。
- 完成门槛：非假数据的连续对话、延迟/主动发送、时间线区分已发与未发；进程重启后重复 requestId 不重复可见投递；HDS 原有相关测试不回退。

## T07 — 角色卡解析、导出与世界书格式

- 依赖：T04。
- 工作：按 03-CARD-IMPORT 实现 JSON、PNG、原始字段保留、大小限制、合成样本；接入 Android SAF；实现 inspect/commit 两阶段及重复文件处理。CHARX 在主格式稳定后完成资源子集。
- 交付：纯解析包、fixture 清单、schema/往返测试、Android 文件导入页面。
- 完成门槛：有效卡保留未知字段；损坏/超限/路径越界无半写入；取消文件选择可继续再次选择；V3 与双元数据行为明确。

## T08 — 角色映射与世界书真正进入叙事

- 依赖：T06、T07。
- 工作：增加 narrator 中角色提示槽、示例和 lorebook 块；保留 HDS 格式合约；实现宏、关键词、预算、有界递归/正则。开场白通过投递/账本入口提交，设置变更有快照。
- 交付：映射说明、PromptTrace、差分与真实 API 观察报告。

## T09 — 极简手机界面

- 依赖：T06、T07、T08。
- 工作：实现四个主页面、首次引导、卡预览、对话/剧情区分、记忆/日程详情、模型任务分配、高级配置入口和运行状态。
- 交付：屏幕录制或截图、窄屏/键盘/深色/大字体检查。
- 完成门槛：首次使用不必打开终端；用户从导入卡到开始运行路径完整；未实现按钮不得显示成功；设置草稿不会被状态刷新覆盖。

## T10 — 产品化 QQ 渠道与登录

- 依赖：T03、T05、T06。
- 工作：将验证链变成安装/登录/重连/退出流程；真实 OneBot Bot 身份、账号与群/私聊白名单、合并消息、群意愿、图片/引用处理；密钥与 WebUI 认证分开管理。
- 交付：QQ 首次配置向导、渠道状态与异常报告。
- 完成门槛：同一手机上的二维码展示、保存/刷新/切换 QQ 完成登录的实际流程经过验证；不能默认必须第二台电脑。退登不删剧情；未授权群不会回复；掉线不是 healthy。

## T11 — 产品化 QQ 空间及叙事联动

- 依赖：T10、T03。
- 工作：保留 HDS 发帖/评论/点赞限流、intent、审计；好友 feed 去重，读取自己动态评论增量并转入剧情；提供空间视图与动作状态。
- 交付：空间端到端报告、错误/超时/限额案例。
- 完成门槛：五类核心动作均有证据；unknown 不重发；读动态不会无限触发模型推进；多账号动作不会串号；达到配额后确实停止。缺项仍阻断全功能首版。

## T12 — HDS 功能保真与媒体

- 依赖：T06、T08、T10。
- 工作：完成 T01 的每项 feature-parity；日程、Alter、Urge、Agency、世界播种、长期指导、模型路由、压缩、Embedding、作品/网页观察等已有能力逐项给手机入口或经适配高级入口。验证图片、贴纸、音频、网页读取所需的依赖与路径。
- 交付：完整功能矩阵、原版与移动宿主的相同 fixture 差分结果。
- 完成门槛：所有用户范围内项目非“静默丢失”；外部 provider 不支持时显示能力原因；保留原版语音语义，不冒充已有 TTS。高耗资源能力可按需安装/启用，但不能宣称未测的 Android 兼容。

## T13 — 后台、恢复与成本控制

- 依赖：T05、T06、T11。
- 工作：合法前台服务、通知入口、用户停止、进程回收恢复、Doze 和厂商后台策略；基于持久意图重建调度，限制离线 catch-up；用量及费用估算注明来源，设置可配置日调用预算。
- 交付：前后台/断网/时间变化测试记录，运行策略说明。
- 完成门槛：强制停止后不承诺继续运行；正常恢复不重复消息/空间动作；预算截止后停止新增后台调用并告知；模拟时钟验证不改变用户手机系统时间。

## T14 — 备份恢复与电脑数据迁移

- 依赖：T06、T07。
- 工作：设计备份版本和清单、SQLite 一致快照、媒体相对引用、脱敏配置；恢复预览/验证/原子切换；固定基线的电脑 HDS 数据导入，处理旧账号映射和本地媒体路径。
- 交付：往返样本与记录数量/内容哈希比对报告。
- 完成门槛：恢复后故事、事实、意图和资产一致；API Key/QQ 会话默认不导出；不兼容或坏包不破坏当前库；恢复后需要的重登录提示清楚。

## T15 — 升级、回滚与可复现发布流水线

- 工作：应用/运行时/HDS/QQ 后端独立版本与兼容清单；固定资源、校验、迁移前备份、回滚策略；可信 Gradle wrapper；release 签名由环境提供。
- 交付：从干净环境构建的 APK、校验和、源代码清单、旧版升级测试。
- 完成门槛：旧版数据升级成功、失败恢复成功；不依赖原项目私钥；源码修改可在包内版本/行为验证；授权未通过的组件不进入公开包。

## T16 — 设备矩阵与资源优化

## 2. 每项任务的交接模板

```text
任务 ID：
本次目标与完成状态：
输入提交与最终提交：
修改文件及原因：
HDS 行为是否变化：
执行命令 / 设备 / 日志位置：
通过 / 失败 / 未执行的用例：
迁移和回滚方式：
新增依赖与来源：
未决问题及下一任务：
```

模型交接以代码和证据为准，不以“已实现基本功能”等概括为准。测试只扩展到变化与风险覆盖所需范围，不为文案改动制造大量无价值测试。
